# bunny_js

Four Bunny Edge Scripts, each deployed as **one bundled file**:

| Script        | Serves                    | What                                                                       |
| ------------- | ------------------------- | -------------------------------------------------------------------------- |
| `searchapi`   | `web-agent.fretchen.eu`   | Web-search (`/search`) and single-page-fetch (`/fetch`) — paid per call    |
| `llm`         | `llm-agent.fretchen.eu`   | Mistral chat completions (OpenAI shape) — paid per request, metered        |
| `mcp`         | `mcp-agent.fretchen.eu`   | Stateless MCP gateway (JSON-RPC 2.0 over POST) relaying both tools' calls  |
| `facilitator` | `facilitator.fretchen.eu` | The x402 facilitator (`/verify`, `/settle`, `/supported`, `/openapi.json`) |

All four are live. Three of them are **sellers** — unpaid requests get the honest `402` +
`Payment-Required` challenge; retry with the payment attached settles and returns the
result. The channel state lives in the shared S3 bucket, claimed by `scw_js`'s
`llmx402cron` (the edge has no cron), which is also why `x402_facilitator/` keeps only
`walletreportcron`.

The sellers are ERC-8004-registered agents on Base. Every origin serves:

- `GET /` — the **agent root page**: capability, prices, contracts and a no-wallet curl,
  generated by [`src/discovery.ts`](./src/discovery.ts) from the committed spec
  (nothing hand-restated). The genimg origin serves its twin from `scw_js`.
- `GET /openapi.json` — the live OpenAPI 3.1 discovery contract.
- `GET /.well-known/agent-registration.json` — the ERC-8004 registration file
  (also the on-chain `agentURI`); `GET /.well-known/oasf.json` — the OASF record.

Security posture: [`SECURITY.md`](./SECURITY.md). Agent rules: [`AGENTS.md`](./AGENTS.md).

## Commands

```bash
npm run build          # tsdown bundle: dist/searchapi.js, dist/llm.js, dist/mcp.js, dist/facilitator.js
npm run dev:<name>     # local serve of one twin via Deno on 127.0.0.1 (source, no build; --env-file=.env baked in)
npm test               # vitest
npm run check          # typecheck + lint + format + tests
npm run deploy         # build, then `bunny scripts deploy dist/searchapi.js`
```

- Dev for the paid path needs `NFT_WALLET_PUBLIC_KEY` + `RECEIVER_AUTHORIZER_PRIVATE_KEY`
  in `.env`; extra args go after `--`.
- Ordering (repo rule): `npm run build` in `shared/chain-utils` and `shared/s3-utils`
  first — they are `file:` dependencies.

## Architecture

- `src/routes.ts` (searchapi), `src/llm_routes.ts`, `src/mcp_routes.ts` and
  `src/facilitator/facilitator_routes.ts` are the **only native-routing code**: web-standard
  `Request`/`Response` handlers that mirror the Scaleway twins' route tables and ordering
  rules.
- Everything else under `src/` is **ported verbatim** from `scw_js` (the shared seller
  stack, services with the SSRF defence, schemas, discovery, favicon) or from
  `x402_facilitator/` (the payment core, `src/facilitator/`), with two deliberate
  deviations: `logger.ts` is a pino-shaped console shim that also flushes to Scaleway
  Cockpit/Loki, and `utils.ts` ports only the platform-neutral half (no Scaleway envelope).
- `src/runtime-shims.ts` — pins the Node `Buffer`/`process` globals the ported code assumes;
  imported FIRST by each entry.

### Facilitator specifics

- **Recipient gating is an allowance gate, not a whitelist**: the recipient must have
  `approve()`d the facilitator wallet for the fee **in the settled token**; under-approval
  is rejected with `insufficient_fee_allowance`. `BATCH_SETTLEMENT_TEST_WALLETS`
  (`src/facilitator/x402_whitelist.ts`) is the only bypass, honored on testnets only.
- **The fee pull** (`src/facilitator/x402_fee.ts`) is a second transaction right after the
  settlement: it signs via viem's shared `nonceManager`, retries pre-broadcast refusals
  (`FEE_SEND_ATTEMPTS` × 2 s), and never resends anything that may have been broadcast.
  A settlement stuck as `settlement_pending` on a healthy RPC after a deploy means a dropped
  transaction the nonce manager already counted — restarting the isolate clears it.

## Environment / secrets (bunny script env vars)

Set per script via `bunny scripts env set`; `--secret` encrypts, plain stays inspectable.
Criterion: **if a value authenticates, signs, or bills, it is a secret.**

Sellers (`searchapi`, `llm`, `mcp` — the same channel tuple as the retired Scaleway
functions, or the channels are unusable):

| Variable                                      | kind           | Use                                                                             |
| --------------------------------------------- | -------------- | ------------------------------------------------------------------------------- |
| `NFT_WALLET_PUBLIC_KEY`                       | plain          | receiver / payTo (public address)                                               |
| `RECEIVER_AUTHORIZER_PRIVATE_KEY`             | `--secret`     | signs batch-settlement locks / refund authorizations                            |
| `BRAVE_API_KEY` (searchapi, mcp)              | `--secret`     | Brave search API (metered)                                                      |
| `MISTRAL_API_KEY` (llm, mcp)                  | `--secret`     | upstream chat model                                                             |
| `SCW_S3_BUCKET` / `SCW_S3_REGION`             | plain          | channel store (`my-imagestore` / `nl-ams`; no `.env` fallback — set explicitly) |
| `SCW_ACCESS_KEY` + `SCW_SECRET_KEY`           | `--secret`     | channel storage on S3                                                           |
| `RPC_URL_EIP155_10`, `RPC_URL_EIP155_8453`    | `--secret`     | viem chain reads; unset = viem public defaults                                  |
| `SCW_COCKPIT_PUSH_TOKEN` / `COCKPIT_LOKI_URL` | secret / plain | Cockpit log-flush auth pair                                                     |

Facilitator — its own script env (mirrors `x402_facilitator/serverless.yml`):
`FACILITATOR_FEE_AMOUNT` (plain, atomic units), `BATCH_SETTLEMENT_TEST_WALLETS` (plain),
`FACILITATOR_WALLET_PRIVATE_KEY` (`--secret`, signs settles and fee pulls),
`RPC_URL_EIP155_*` (`--secret`), plus the Cockpit pair.

## Known limits / decisions

- **Bunny's runtime is Deno 1.x, not Node.** Assumes only what `src/runtime-shims.ts` pins;
  Node builtins must be imported through the `node:` prefix.
- **1 MB single-file bundle limit.** tsdown emits one file per script (`codeSplitting:
false`); measured well under the cap (run `npm run build` to check).
- **The CDN in front rewrites `no-store` to `no-cache`.** Still safe: the responses carry no
  validators, so every hit goes to the origin and paid responses cannot be replayed.
- **Non-latin1 header bytes** are escaped as JSON `\uXXXX` in payment headers — lossless
  for any JSON-parsing client.
- **50 subrequests per request** — comfortably within budget for one paid request; fetch
  storms are not.
- **No cron at the edge** — `llmx402cron` (`scw_js`) claims these channels;
  `walletreportcron` (`x402_facilitator/`) sends the weekly wallet report.

## Deploying

Bunny publishes whichever deployment happened **last** — CLI and Actions interoperate, and
the next push to `main` restores the committed state.

1. **GitHub Actions** (preferred): `.github/workflows/deploy-bunny-js.yml` builds on push to
   `main` touching `bunny_js/**` or the shared libs and publishes all four bundles. Needs
   the per-script secrets `BUNNYJS_*`, `BUNNYLLM_*`, `BUNNYMCP_*`, `BUNNYFACILITATOR_*`
   (`<NAME>_SCRIPT_ID` + `<NAME>_DEPLOY_KEY`, from the dashboard: Script → Deployments →
   Settings). The workflow ships code only — env vars and secrets live on the script itself.
2. **Manual**: `npm run deploy` for searchapi; the others by id:
   `bunny scripts deploy dist/llm.js <id>` etc.

First-time setup (once, not in CI): `bunny scripts create --type standalone` creates each
script (only searchapi takes the `.bunny/script.json` link; the others use `--no-link`),
then `bunny scripts env set` per the tables above, then the smoke test:
`curl -D - 'https://<origin>/search?q=x402'` → 402 + `Payment-Required` header.

The trial matrix and facilitator-cutover checklist of the port are preserved in git history.
